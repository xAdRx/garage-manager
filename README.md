# Garage Manager

A simple REST API in Go for listing vehicles (cars and motorcycles). It uses
only the standard library `net/http` router, with Swagger docs generated by
[swag](https://github.com/swaggo/swag) and shown with the
[Scalar](https://github.com/scalar/scalar) UI.

The `frontend/` folder holds a React web app that shows the garage and has an
Owner Panel for adding vehicles. See [Frontend](#frontend).

## Requirements

- Go 1.26 or later
- OpenSSL (to create a local TLS certificate for HTTPS)
- Node.js 22 or later and npm (only for the frontend)

## Setup

1. Clone the repository:

   ```sh
   git clone git@github.com:xAdRx/garage-manager.git
   cd garage-manager
   ```

2. Download the dependencies:

   ```sh
   go mod download
   ```

3. Create a self-signed TLS certificate in `certs/`. The server does not
   start without it. These files are git-ignored, so do not commit them.

   ```sh
   openssl req -x509 -newkey rsa:2048 -nodes \
     -keyout certs/key.pem -out certs/cert.pem -days 365 \
     -subj "/CN=localhost" \
     -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
   ```

   This certificate is for local development only. Use a real certificate
   (for example from Let's Encrypt) in production.

4. Install the frontend packages:

   ```sh
   cd frontend
   npm install
   cd ..
   ```

## Run

The program has two parts, and each one runs in its own terminal. Start the
API first.

1. **Terminal 1, the API.** From the project root:

   ```sh
   go run .
   ```

   Wait for `HTTP listening on :5000` and `HTTPS listening on :5001`.

2. **Terminal 2, the frontend.** From the project root:

   ```sh
   cd frontend
   npm run dev
   ```

3. Open <http://localhost:5173> in the browser.

To stop either part, press `Ctrl+C` in its terminal.

| Part                       | Address                        |
|----------------------------|--------------------------------|
| Web app (garage)           | <http://localhost:5173>        |
| Web app (Owner Panel)      | <http://localhost:5173/owner>  |
| API over HTTP              | <http://localhost:5000>        |
| API over HTTPS             | <https://localhost:5001>       |
| API docs (Scalar)          | <http://localhost:5000/docs>   |

If the garage page says "Can't load vehicles", the API in terminal 1 is not
running.

The garage starts with 4 default vehicles:

| Type       | Brand     | Model       | Year | Doors |
|------------|-----------|-------------|------|-------|
| Car        | Chevrolet | Corvette C7 | 2018 | 2     |
| Car        | RAM       | 1500        | 2025 | 4     |
| Motorcycle | Yamaha    | FJR1300     | 2005 | —     |
| Car        | XPeng     | P7+         | 2027 | 5     |

The data is kept in memory only, so vehicles you add are lost when the API
restarts.

### API only

To run the API without the frontend, use only step 1. To build an API binary
instead of `go run`:

```sh
go build -o restapi .
./restapi
```

Run the binary from the project root, because it reads the certificate from
`certs/` relative to the current directory.

## API

### `GET /vehicles`

Returns all vehicles. Every filter is optional, and filters combine with AND.

| Query parameter | Description                                |
|-----------------|--------------------------------------------|
| `type`          | `car` or `motorcycle` (case-insensitive)   |
| `brand`         | Brand contains this text, case-insensitive |
| `model`         | Model contains this text, case-insensitive |
| `year`          | Exact production year                      |
| `minYear`       | Production year from (inclusive)           |
| `maxYear`       | Production year to (inclusive)             |

For example, with the default vehicles `brand=e` matches both Chevrolet and
XPeng.

In a raw URL, write `+` as `%2B`, because `+` means a space in a query string:
use `model=p7%2B` to find the XPeng P7+. The frontend encodes this for you.

An empty result returns `200` with `[]`. An invalid filter value returns `400`.

Examples:

```sh
curl http://localhost:5000/vehicles
curl "http://localhost:5000/vehicles?type=car&minYear=2021"
curl -k https://localhost:5001/vehicles
```

The `-k` flag tells curl to accept the self-signed certificate.

### `POST /vehicles`

Adds a car or motorcycle and returns it with status `201`. The server
generates the id.

| Field        | Type    | Rules                                                  |
|--------------|---------|--------------------------------------------------------|
| `type`       | string  | Required: `car` or `motorcycle`                        |
| `brand`      | string  | Required, not empty                                    |
| `model`      | string  | Required, not empty                                    |
| `year`       | integer | Required, from 1886 to next year                       |
| `doors`      | integer | Car only: optional, 1 to 10                            |
| `hasSidecar` | boolean | Motorcycle: optional, default `false`. Car: only `false`, ignored |

Unknown fields, `doors` on a motorcycle, `hasSidecar: true` on a car, or a
value that breaks a
rule return `400`. A body larger than 1 MB returns `413`.

Examples:

```sh
curl -X POST http://localhost:5000/vehicles \
  -H "Content-Type: application/json" \
  -d '{"type":"car","brand":"Skoda","model":"Octavia","year":2023,"doors":5}'

curl -X POST http://localhost:5000/vehicles \
  -H "Content-Type: application/json" \
  -d '{"type":"motorcycle","brand":"Ural","model":"Gear Up","year":2022,"hasSidecar":true}'
```

Vehicle ids (GUIDs) are generated again each time the server restarts.

### API docs

- Scalar UI: <http://localhost:5000/docs>
- OpenAPI (Swagger 2.0) spec: <http://localhost:5000/docs/openapi.json>

The Scalar UI loads its script from a CDN, so the docs page needs internet
access.

## Updating the API docs

The spec in `docs/` is generated from the `@Summary`, `@Param`, `@Router` and
other annotation comments on the handlers. Do not edit `docs/` by hand.

1. Install the swag CLI (once):

   ```sh
   go install github.com/swaggo/swag/cmd/swag@v1.16.4
   ```

2. After changing any annotation, regenerate the spec:

   ```sh
   swag init
   ```

   If `swag` is not on your `PATH`, run `~/go/bin/swag init` instead.

## Frontend

A React + TypeScript app built with [Vite](https://vite.dev).

- **Garage** (`/`): filters on top (type, brand, model, year range) and every
  vehicle below as a tile in a parking bay. Filters update the list as you type.
- **Owner Panel** (`/owner`, button in the top right): a form to add a car or
  motorcycle. Doors and sidecar are optional.

The Owner Panel has no login yet, so anyone who can open the site can add
vehicles.

### How the frontend reaches the API

To start the frontend, see [Run](#run). The app calls the API under `/api`. The Vite dev server forwards those requests
to `http://localhost:5000` and removes the `/api` prefix, so the browser talks
to one origin and the API needs no CORS setup. To use another API address, set
`API_URL`:

```sh
API_URL=http://localhost:5100 npm run dev
```

### Other commands

Run these inside `frontend/`:

| Command           | What it does                                     |
|-------------------|--------------------------------------------------|
| `npm run build`   | Type-checks and builds static files into `dist/` |
| `npm run preview` | Serves the `dist/` build locally                 |
| `npm run lint`    | Lints the code with oxlint                       |

The `/api` forwarding exists only in the dev server. To deploy the `dist/`
build, serve it behind a web server or proxy that forwards `/api/*` to the Go
API in the same way.

## Project structure

```
.
├── main.go                    Entry point: ports, certificate paths, API info
├── server/server.go           Server setup, route registration, HTTP/HTTPS listeners
├── handlers/
│   ├── vehicles.go            GET and POST /vehicles handlers and default data
│   ├── vehicle_request.go     POST /vehicles request body and validation
│   ├── vehicle_filter.go      Query filter parsing and matching
│   └── docs.go                Scalar UI and OpenAPI spec handlers
├── models/
│   ├── vehicle.go             Vehicle base struct, VehicleType, VehicleItem interface
│   ├── car.go                 Car (embeds Vehicle)
│   └── motorcycle.go          Motorcycle (embeds Vehicle)
├── docs/                      Generated Swagger spec (do not edit)
├── certs/                     Local TLS certificate and key (git-ignored)
└── frontend/                  React web app
    ├── vite.config.ts         Dev server and /api forwarding to the Go API
    └── src/
        ├── main.tsx           Entry point, router setup
        ├── App.tsx            Page routes: / and /owner
        ├── styles.css         Garage theme and layout
        ├── api/vehicles.ts    API client and types
        ├── hooks/             useDebounced (delays filter requests while typing)
        ├── components/        Header, FilterBar, VehicleTile, VehicleIcon
        └── pages/             GaragePage, OwnerPanelPage
```
